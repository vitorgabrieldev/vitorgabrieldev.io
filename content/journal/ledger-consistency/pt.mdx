## O Princípio de Partidas Dobradas

Partidas dobradas não é uma feature optional. É uma **lei da física contábil**: cada movimento de dinheiro cria dois registros. Um débito em X exige um crédito em Y. Sempre. Sem exceção.

Por quê? Porque facilita auditoria: o total de débitos deve sempre = total de créditos. Se não bate, você perde dinheiro (ou alguém ganhou no seu prejuízo).

## O Custo de Não Fazer de Primeira

Você pensa: "Vou colocar um campo `balance` na tabela de contas. Rápido, simples."

```php
// ❌ ERRADO: Tracking de saldo direto
DB::table('accounts')->where('id', $from)->decrement('balance', $amount);
DB::table('accounts')->where('id', $to)->increment('balance', $amount);
```

**Dia 1**: Funciona.
**Mês 3**: Um débito falha na metade. `$from` decrementou, mas `$to` nunca incrementou. Você criou R$1.000 do nada. Você não sabe aonde.
**Mês 6**: Cliente diz "meu saldo tá estranho". Você não consegue auditar. Precisa checar logs manualmente. Leva 8 horas pra achar um erro de R$0,01 que aconteceu em Janeiro.
**Mês 12**: Você tem 300 discrepâncias. Precisa refatorar tudo. 200 horas de trabalho. Banco não sabe se passou pro cliente ou ficou perdido. Legal.

## Partidas Dobradas: Como Funciona De Verdade

Cada transação é **dois registros indivisíveis**.

```php
// ✅ CORRETO: Ledger com duas linhas atômicas
DB::transaction(function () use ($from, $to, $amount) {
  // Débito
  Ledger::create([
    'account_id' => $from,
    'type' => 'debit',
    'amount' => $amount,
    'transaction_id' => Str::uuid(),
    'description' => "Transfer to {$to->name}",
    'created_at' => now(),
  ]);
  
  // Crédito
  Ledger::create([
    'account_id' => $to,
    'type' => 'credit',
    'amount' => $amount,
    'transaction_id' => Str::uuid(), // MESMA! Ligam as duas
    'description' => "Transfer from {$from->name}",
    'created_at' => now(),
  ]);
});
```

**Por que dois UUIDs iguais?** Para depois você conseguir rastrear "quais dois registros pertencem à mesma transação".

## O Teste: Você Consegue Auditar?

Auditoria verdadeira é assim:

```php
// Soma todas as linhas
$totalDebits = Ledger::where('type', 'debit')->sum('amount');
$totalCredits = Ledger::where('type', 'credit')->sum('amount');

if ($totalDebits !== $totalCredits) {
  // Você criou ou destruiu dinheiro
  throw new LedgerImbalanceException("Missing: R$ {$totalDebits - $totalCredits}");
}

// Teste de transação órfã
$orphanedDebits = Ledger::where('type', 'debit')
  ->whereNotExists(function ($query) {
    $query->select(DB::raw(1))
      ->from('ledgers as credits')
      ->where('credits.type', 'credit')
      ->whereRaw('credits.transaction_id = ledgers.transaction_id');
  })
  ->get();

if ($orphanedDebits->isNotEmpty()) {
  // Débito sem crédito correspondente = PROBLEMA
  Log::error('Orphaned ledger entries', ['count' => $orphanedDebits->count()]);
}
```

## Scenario Real: Por Que Isso Mata Seu App

Você tá construindo um fintech. Dia 30, você tá em produção com 10K usuários.

Um cliente faz uma transferência no horário de pico.

```
1. Servidor A decrementa conta origem
2. Network hiccup
3. Servidor B não consegue incrementar conta destino
4. Transação meio-feita = R$500 desapareceu
```

**Sem ledger de partidas dobradas:**
Você não sabe o que aconteceu. Os logs dizem "erro na query", mas qual query? De quem? Pra onde foi o dinheiro?

**Com ledger de partidas dobradas:**
```php
// Você roda audita de manhã
$unmatched = Ledger::select('*')
  ->where(function ($q) {
    $q->whereNotExists(function ($subquery) {
      $subquery->select(1)
        ->from('ledgers as paired')
        ->whereRaw('paired.transaction_id = ledgers.transaction_id')
        ->where('paired.type', '!=', DB::raw('ledgers.type'));
    });
  })
  ->get();

// Encontra o débito órfão
echo "Débito órfão: R$500 da conta {$unmatched->first()->account_id}";
echo "Transaction ID: {$unmatched->first()->transaction_id}";

// Você recupera o erro do log com transaction_id
Log::search('transaction_id', $unmatched->first()->transaction_id);
// Encontra: "Stripe API timeout, retry later"

// Agora você pode:
// 1. Reabrir a transação
// 2. Completar o crédito
// 3. Notificar o cliente
```

## Estrutura de Verdade: 3 Tabelas

```sql
-- 1. Tabela de contas (apenas para reference)
CREATE TABLE accounts (
  id BIGINT PRIMARY KEY,
  name VARCHAR,
  created_at TIMESTAMP
);

-- 2. Tabela de ledger (a FONTE DE VERDADE)
CREATE TABLE ledgers (
  id BIGINT PRIMARY KEY,
  account_id BIGINT NOT NULL,
  transaction_id UUID NOT NULL, -- Liga débito + crédito
  type ENUM('debit', 'credit') NOT NULL,
  amount DECIMAL(12, 2) NOT NULL,
  description VARCHAR,
  created_at TIMESTAMP NOT NULL,
  
  INDEX (transaction_id), -- Achar par debit/credit
  INDEX (account_id, created_at), -- Balanço de conta
  INDEX (type, created_at) -- Auditoria global
);

-- 3. Tabela de saldo (cache, recalculável)
CREATE TABLE account_balances (
  id BIGINT PRIMARY KEY,
  account_id BIGINT UNIQUE NOT NULL,
  balance DECIMAL(12, 2) NOT NULL, -- Soma das linhas do ledger
  calculated_at TIMESTAMP,
  
  -- Se esse saldo bate com SUM(ledger.amount WHERE type='credit') - SUM(ledger.amount WHERE type='debit'),
  -- seu sistema está saudável
);
```

**Regra de Ouro:** Nunca altere `account_balances` direto. É CACHE. Sempre recalcule a partir de `ledgers`.

## Implementação Segura

```php
class TransferService
{
  public function transfer(Account $from, Account $to, $amount): Transaction
  {
    return DB::transaction(function () use ($from, $to, $amount) {
      $txnId = Str::uuid();
      
      // Validação antes de tocar em nada
      if ($from->balance < $amount) {
        throw new InsufficientFundsException();
      }
      
      // LINHA 1: Débito
      Ledger::create([
        'account_id' => $from->id,
        'transaction_id' => $txnId,
        'type' => 'debit',
        'amount' => $amount,
        'description' => "Transfer to {$to->name}",
        'created_at' => now(),
      ]);
      
      // LINHA 2: Crédito (se falhar, a transação inteira reverte via DB::transaction)
      Ledger::create([
        'account_id' => $to->id,
        'transaction_id' => $txnId,
        'type' => 'credit',
        'amount' => $amount,
        'description' => "Transfer from {$from->name}",
        'created_at' => now(),
      ]);
      
      // Recalcula saldos (isso NÃO é realmente necessário toda vez, mas deixo pra ser claro)
      AccountBalance::updateOrCreate(
        ['account_id' => $from->id],
        ['balance' => $from->getBalanceFromLedger()]
      );
      
      AccountBalance::updateOrCreate(
        ['account_id' => $to->id],
        ['balance' => $to->getBalanceFromLedger()]
      );
      
      return new Transaction([
        'id' => $txnId,
        'from' => $from,
        'to' => $to,
        'amount' => $amount,
        'status' => 'completed',
      ]);
    });
  }
}

// Helper: Calcular saldo de verdade
Account::macro('getBalanceFromLedger', function () {
  $credits = Ledger::where('account_id', $this->id)
    ->where('type', 'credit')
    ->sum('amount');
  
  $debits = Ledger::where('account_id', $this->id)
    ->where('type', 'debit')
    ->sum('amount');
  
  return $credits - $debits;
});
```

## Implementar Cedo: 2 Horas

**Vs Retrofitar em Produção: 200 Horas + Dor de Cabeça**

Se você não tem usuários ainda:

1. Cria a tabela `ledgers`
2. Refatora cada transação pra criar dois registros atômicos
3. Adiciona teste: verifica se débitos = créditos após cada operação
4. Done. Seu sistema é auditável pro resto da vida.

Se você já tá em produção com `balance` field:

1. Backfill: cria ledger entries a partir do histórico
2. Migração: move 10K transações, valida
3. Testes: roda auditoria nightly pra detectar discrepâncias
4. Cutover: liga o novo sistema, mata o antigo
5. Monitoramento: alerta se débitos !== créditos

Isso não é revisão, é **rearquitetura**. Toma meses.

## Checklist: Seu Ledger É Seguro?

**SIM se:**
• Cada transação cria EXATAMENTE 2 linhas (debit + credit)
• Mesmo `transaction_id` liga as duas
• SUM(débitos) = SUM(créditos) sempre
• Você consegue auditar qualquer conta em 30 segundos
• Histórico é imutável (append-only)

**NÃO se:**
• Você atualiza/deleta registros de ledger
• Tem um campo `balance` que você atualiza direto
• Transações incompletas sem rollback
• Sem índices em transaction_id

## Resumo

Partidas dobradas são o alicerce. Implementar cedo = 2 horas. Retrofitar = 200 horas + noites mal dormidas.
