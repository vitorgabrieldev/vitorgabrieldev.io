## O Problema: HTTP Logic Poluído

Controllers que fazem queries, Controllers que manipulam dados, Controllers que orquestram transações — tudo espalhado.

## A Estrutura Correta

**Controller** — apenas adaptador HTTP
• Desserializa request
• Valida input
• Chama Service
• Serializa response

**Service** — orquestração de negócio
• Validações de domínio
• Regras de negócio
• Transações DB
• Coordena Repositories

**Repository** — acesso puro a dados
• Queries sem lógica
• Mutations sem lógica
• Zero regras de negócio

**Model** — representação de dados
• Relacionamentos
• Casts e accessors
• Validações básicas

## Exemplo: Transferência Bancária

### ❌ ERRADO (tudo no Controller)

```php
class TransferController {
  public function transfer(Request $request) {
    $from = Account::find($request->from_id);
    $to = Account::find($request->to_id);
    if ($from->balance < $request->amount) abort(400);
    $from->balance -= $request->amount;
    $to->balance += $request->amount;
    $from->save();
    $to->save();
    AuditLog::create([...]);
  }
}
```

**Problemas:**
- Impossível testar isolado
- Lógica espalhada
- Reutilização zero
- Difícil de mudar
- Sem transação de verdade

### ✅ CORRETO (Controller delega)

```php
class TransferController {
  public function transfer(Request $request, TransferService $service) {
    $validated = $request->validate([...]);
    $result = $service->transfer($validated);
    return response()->json($result);
  }
}

class TransferService {
  public function transfer(array $data): array {
    return DB::transaction(function () use ($data) {
      $from = $this->accountRepo->findOrFail($data['from_id']);
      $to = $this->accountRepo->findOrFail($data['to_id']);
      
      // Validações de negócio
      if (!$from->canTransfer($data['amount'])) {
        throw new InsufficientFundsException();
      }
      
      // Ledger duplo
      $this->ledger->debit($from, $data['amount']);
      $this->ledger->credit($to, $data['amount']);
      
      // Auditoria
      $this->auditLog->record('transfer', $data);
      
      return ['success' => true, 'txn_id' => ...];
    });
  }
}

class AccountRepository {
  public function findOrFail(int $id): Account {
    return Account::findOrFail($id);
  }
}
```

**Vantagens:**
- Testável (testa Service isolado)
- Transação real com rollback automático
- Auditória garantida
- Reutilizável (HTTP, CLI, Queue)
- Fácil de mudar

## Laravel 12: Actions vs Services

**Quando usar Actions (Spatie)**
→ Operações simples e unitárias
→ Um único fluxo de dados
→ Exemplos: CreatePost, SendEmail, UpdateProfile

**Quando usar Services**
→ Fluxos complexos com múltiplos passos
→ Múltiplas entidades envolvidas
→ Exemplos: Onboarding, Pagamento, Migração

## Benefícios Práticos

**Testabilidade**
• Testa Service sem Controller
• Testa Controller sem Service (mock)
• Cobertura de testes real

**Reusabilidade**
• Mesma lógica por HTTP, CLI, Queue
• Mesma lógica por diferentes controllers
• Sem duplicação

**Manutenibilidade**
• Lógica em um único lugar
• Mudanças seguras e isoladas
• Debugging direto ao ponto

**Escalabilidade**
• Estrutura preparada para crescimento
• Fácil extrair para microsserviço
• Separação clara de responsabilidades

## A Regra de Ouro

**Se toca em database + lógica = tira do Controller.**

Não é sobre microserviços ou complexidade — é sobre separação clara. A estrutura de camadas funciona em qualquer escala.
