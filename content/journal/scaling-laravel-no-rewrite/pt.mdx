## O Mito da Reescrita

Seu Laravel tá lento. Você quer reescrever em Go, Node, Rust.

**Pare.**

90% dos cases que vi, o problema não é Laravel — é:
• Queries N+1
• Sem cache de homepage
• Processing síncrono de jobs pesados
• Índices faltando no banco
• Serialização ineficiente

## Diagnóstico: Onde Você Tá Lento?

### 1. Check N+1 Queries

```php
// ❌ ERRADO
$users = User::all(); // 1 query
foreach ($users as $user) {
  echo $user->profile->bio; // 1 query por usuário
}
// Total: 1 + 101 queries para 100 usuários

// ✅ CORRETO
$users = User::with('profile')->get(); // 2 queries
foreach ($users as $user) {
  echo $user->profile->bio;
}
```

**Como encontrar N+1:**
• `php artisan debugbar` - QueryLogger mostra duplicatas
• `DB::listen()` - log todas as queries em produção
• Procure por queries idênticas em loops

```php
DB::listen(function ($query) {
  if ($query->time > 50) { // Queries lentas
    Log::warning('Slow query', [
      'sql' => $query->sql,
      'bindings' => $query->bindings,
      'time' => $query->time,
    ]);
  }
});
```

### 2. Profile com Blackfire

```bash
brew install blackfire-agent
blackfire-cli run curl https://seu-app.com
```

**Você verá:**
• Função mais lenta
• Chamadas repetidas
• Tempo em DB vs PHP
• Memory leaks

## Estratégia 1: Caching em Camadas

### Cache Level 1: HTTP Response (Browser)

```php
// resources/views/products/index.blade.php
<meta http-equiv="cache-control" content="max-age=3600">

// Laravel (middleware)
Route::middleware('cache:3600')->group(function () {
  Route::get('/products', [ProductController::class, 'index']);
});
```

### Cache Level 2: Application Cache (Redis)

```php
// app/Http/Controllers/ProductController.php
public function index()
{
  return Cache::remember('products.all', 3600, function () {
    return Product::with('category')
      ->select('id', 'name', 'price', 'category_id')
      ->get();
  });
}

// Quando atualizar um produto
public function update(Request $request, Product $product)
{
  $product->update($request->validated());
  Cache::forget('products.all'); // Invalida cache
  return redirect()->back();
}
```

### Cache Level 3: Query Result Cache

```php
// app/Repositories/ProductRepository.php
public function getActivePriced()
{
  $key = 'products:active:priced';
  $ttl = now()->addHours(1);
  
  return Cache::remember($key, $ttl, function () {
    return Product::where('active', true)
      ->whereNotNull('price')
      ->select('id', 'name', 'price')
      ->orderBy('name')
      ->get();
  });
}
```

### Cache Level 4: Database Query Cache (Índices)

```php
// database/migrations/2026_04_18_add_indexes.php
Schema::table('products', function (Blueprint $table) {
  $table->index('active');
  $table->index(['category_id', 'active']);
  $table->index('created_at');
  $table->fullText(['name', 'description']);
});

// Query agora é muito mais rápida
Product::whereActive(true)
  ->whereCategory(5)
  ->orderByDesc('created_at')
  ->get();
```

## Estratégia 2: Async Processing com Queues

### Problema: Requisição Bloqueada

```php
// ❌ ERRADO - Usuário espera
public function checkout(Request $request)
{
  $order = Order::create($request->validated());
  
  // Email leva 2 segundos
  Mail::send(new OrderConfirmation($order));
  
  // PDF leva 3 segundos
  $pdf = PDF::generate($order);
  $order->update(['pdf_path' => $pdf]);
  
  // SMS leva 1 segundo
  Twilio::send($order->customer->phone);
  
  return response()->json(['order' => $order]); // 6 segundos depois
}
```

### Solução: Dispatch para Queues

```php
// ✅ CORRETO - Usuário vê resposta em 50ms
public function checkout(Request $request)
{
  $order = Order::create($request->validated());
  
  // Dispatch para background jobs
  SendOrderConfirmation::dispatch($order);
  GenerateOrderPDF::dispatch($order);
  SendOrderSMS::dispatch($order);
  
  return response()->json([
    'order' => $order,
    'status' => 'processing',
  ]); // Resposta imediata
}

// app/Jobs/SendOrderConfirmation.php
class SendOrderConfirmation implements ShouldQueue
{
  use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;
  
  public function __construct(public Order $order) {}
  
  public function handle()
  {
    Mail::send(new OrderConfirmation($this->order));
  }
}

// app/Jobs/GenerateOrderPDF.php
class GenerateOrderPDF implements ShouldQueue
{
  use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;
  
  public function __construct(public Order $order) {}
  
  public function handle()
  {
    $pdf = PDF::generate($this->order);
    $this->order->update(['pdf_path' => $pdf]);
    
    // Dispara outro job quando terminar
    NotifySlackOrderReady::dispatch($this->order);
  }
}
```

## Estratégia 3: Read Models (CQRS Light)

### Problema: Queries Complexas

```php
// ❌ ERRADO - Calcula tudo em tempo real
public function dashboard()
{
  $totalSales = Order::whereMonth('created_at', now()->month)
    ->sum('total');
  
  $topProducts = Order::with('items')
    ->whereMonth('created_at', now()->month)
    ->get()
    ->flatMap->items
    ->groupBy('product_id')
    ->map(fn ($items) => [
      'product_id' => $items->first()->product_id,
      'quantity' => $items->count(),
      'revenue' => $items->sum('price'),
    ])
    ->sortByDesc('revenue')
    ->take(10);
  
  $customerMetrics = Customer::with('orders')
    ->get()
    ->map(fn ($customer) => [
      'id' => $customer->id,
      'name' => $customer->name,
      'lifetime_value' => $customer->orders->sum('total'),
      'order_count' => $customer->orders->count(),
    ]);
  
  return view('dashboard', [
    'totalSales' => $totalSales,
    'topProducts' => $topProducts,
    'customerMetrics' => $customerMetrics,
  ]);
}
```

### Solução: Pré-calcular em Read Model

```php
// database/migrations/2026_04_18_create_dashboard_metrics.php
Schema::create('dashboard_metrics', function (Blueprint $table) {
  $table->id();
  $table->integer('year');
  $table->integer('month');
  $table->decimal('total_sales', 12, 2);
  $table->integer('order_count');
  $table->decimal('avg_order_value', 12, 2);
  $table->timestamps();
  $table->unique(['year', 'month']);
});

Schema::create('top_products_read_model', function (Blueprint $table) {
  $table->id();
  $table->foreignIdFor(Product::class);
  $table->integer('year');
  $table->integer('month');
  $table->integer('quantity_sold');
  $table->decimal('total_revenue', 12, 2);
  $table->timestamps();
  $table->unique(['product_id', 'year', 'month']);
});

// app/Jobs/RecalculateDashboardMetrics.php
class RecalculateDashboardMetrics implements ShouldQueue
{
  public function handle()
  {
    $month = now();
    
    // Calcula agregação pesada
    $metrics = Order::whereYear('created_at', $month->year)
      ->whereMonth('created_at', $month->month)
      ->aggregate([
        'total_sales' => DB::raw('SUM(total)'),
        'order_count' => DB::raw('COUNT(*)')
      ]);
    
    DashboardMetric::updateOrCreate(
      ['year' => $month->year, 'month' => $month->month],
      [
        'total_sales' => $metrics->total_sales,
        'order_count' => $metrics->order_count,
        'avg_order_value' => $metrics->total_sales / $metrics->order_count,
      ]
    );
  }
}

// Controller agora é trivial
public function dashboard()
{
  $metrics = DashboardMetric::whereYear('year', now()->year)
    ->whereMonth('month', now()->month)
    ->first();
  
  $topProducts = TopProductsReadModel::where('year', now()->year)
    ->where('month', now()->month)
    ->orderByDesc('total_revenue')
    ->limit(10)
    ->get();
  
  return view('dashboard', [
    'metrics' => $metrics,
    'topProducts' => $topProducts,
  ]);
}
```

## Estratégia 4: Índices Inteligentes

```php
// database/migrations/2026_04_18_optimize_indexes.php

Schema::table('orders', function (Blueprint $table) {
  // Queries por status + data
  $table->index(['status', 'created_at']);
  
  // Queries por customer
  $table->index('customer_id');
  
  // Sorting por updated_at
  $table->index('updated_at');
  
  // Full-text search
  $table->fullText(['reference_number', 'notes']);
});

Schema::table('customers', function (Blueprint $table) {
  // Filtro por email (login, busca)
  $table->unique('email');
  
  // Sorting
  $table->index('created_at');
});

Schema::table('order_items', function (Blueprint $table) {
  // JOINs rápidos
  $table->index('order_id');
  $table->index('product_id');
});
```

**EXPLAIN ANALYZE**

```php
// Antes do índice: Full table scan (lento)
DB::statement('EXPLAIN ANALYZE SELECT * FROM orders WHERE status = "pending" AND created_at > NOW() - INTERVAL 7 DAY');

// Depois do índice: Index range scan (rápido)
```

## Estratégia 5: Serialização Eficiente

```php
// ❌ ERRADO - Carrega tudo
Route::get('/api/products', function () {
  return Product::with('category', 'reviews', 'inventory')
    ->get();
  // Response: 2MB para 100 produtos
});

// ✅ CORRETO - Seleciona só o necessário
Route::get('/api/products', function () {
  return Product::select('id', 'name', 'price', 'category_id')
    ->with([
      'category:id,name',
      'reviews:id,product_id,rating',
    ])
    ->get();
  // Response: 150KB para 100 produtos
});
```

## Checklist de Performance

**Imediato (antes de segunda-feira):**
• Remover N+1 queries com `with()`
• Usar `select()` para trazer só colunas necessárias
• Adicionar índices nas colunas de `where` e `orderBy`
• Cache da homepage com `Cache::remember()`

**Curto prazo (semana que vem):**
• Mover jobs síncronos para queues
• Implementar read models para dashboards
• Usar Redis para cache de sessão
• Monitor com Blackfire/Debugbar

**Médio prazo (próximo mês):**
• Database replication (read replicas)
• CDN para assets
• Elasticsearch para buscas complexas
• Horizontal scaling com load balancer

## Quando Realmente Precisa Reescrever

**Reescrever SÓ se:**
• Laravel chega em 100K RPS e precisa de 200K
• Latência sub-milissegundo (trading, gaming)
• Problema é real-time (websockets 24/7)
• Team prefere outra linguagem (não é decisão de perf)

**Não é caso para reescrever:**
• App lento mas sem medir
• "Go é mais rápido que PHP"
• Reimplementar do zero "certo"
• Porque novo tech é legal

## Resumo

**90% do tempo, escalar Laravel é:**
1. Encontrar gargalo com profiler
2. Cache em 3 níveis (browser, app, db)
3. Mover work sync → async com queues
4. Read models para agregações
5. Índices inteligentes no banco

**Tempo**: 1-2 sprints
**Custo**: 0 (usa infra que já tem)
**Risco**: Baixo (mudanças incrementais)

Reescrever leva 6 meses, custa 3x mais, e você descobre que Node também tá lento sem cache.
